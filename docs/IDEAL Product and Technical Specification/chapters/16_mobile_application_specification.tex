\chapter{Mobile Application Specification}
The Flutter app currently has a clean welcome foundation. Target structure is feature-first with core config, network, router, theme, shared widgets, and features for auth, home, profile, KYC, deals, approvals, chat, files, notifications, subscription, and settings.
\section{Important Refactor Note}
Any direct Supabase business logic in Flutter is temporary foundation work. Business actions must move behind NestJS API clients.

\section{Current Implementation Status}
The current mobile application has a starter Flutter shell, project identity assets, a welcome screen, and an API configuration foundation pointing to the NestJS base URL. It does not yet contain final auth screens, route guards, Riverpod feature providers, deal screens, Supabase initialization, or production password reset handling on this branch.
