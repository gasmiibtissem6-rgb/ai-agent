\chapter{User Journey and Workflow Specification}
\section{Core Flow Pattern}
Each flow defines actors, preconditions, trigger, user steps, backend actions, database changes, failure cases, and success result.
\section{Deal Approval Flow}
\begin{enumerate}
  \item Creator creates a draft deal.
  \item Creator invites one or more required parties.
  \item Parties review the current version and request changes or approve.
  \item Backend records approvals per party and version.
  \item When every required party approves the same version, backend marks the version approved and locked.
\end{enumerate}
\section{Failure Cases}
Expired invitations, unauthorized deal access, stale version approval, locked-version mutation, subscription limit violation, and missing KYC eligibility must return explicit API errors.
