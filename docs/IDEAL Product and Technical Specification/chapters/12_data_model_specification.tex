\chapter{Data Model Specification}
\section{Core Tables}
Core tables are profiles, companies, company\_members, kyc\_submissions, trust\_counters, deals, deal\_parties, deal\_versions, deal\_approvals, deal\_files, messages, notifications, subscriptions, audit\_logs, admin\_actions, and reports.
\section{Relationships}
A profile belongs to an auth user. A company has many members. A deal has many parties, versions, files, and messages. A version has many approvals. A user has trust counters and notifications. An admin action belongs to an admin profile.

\section{Migration Plan}
Migrations must be numbered and named by intent, for example \texttt{202606190001\_initial\_schema.sql}. The first migration creates enums and tables, the second creates indexes, the third enables RLS, the fourth creates storage buckets and policies, and seed scripts create development-only sample users, deals, parties, and approvals. Rollbacks must be documented before production migration execution.
