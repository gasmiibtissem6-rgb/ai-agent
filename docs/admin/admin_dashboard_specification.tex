\chapter*{Admin Dashboard Specification}
\addcontentsline{toc}{chapter}{Admin Dashboard Specification}

\section*{Purpose}
This document guides \texttt{apps/admin} implementation for IDEAL operations, moderation, KYC review, subscriptions, audit visibility, and system status.

\section*{Architecture Rule}
The Next.js admin dashboard must call NestJS APIs only. It must not write directly to Supabase tables or use the Supabase service role key.

\section*{KYC Review Workflow}
Admin opens the KYC queue, filters submitted records, opens a submission detail page, requests a backend-issued signed preview URL, approves or rejects, enters a mandatory rejection reason when rejecting, and submits the decision to NestJS. The backend writes an admin action, an audit log, updates the profile KYC status, and creates a user notification.

\section*{Admin API Client}
The base URL comes from \texttt{NEXT\_PUBLIC\_API\_BASE\_URL}. The client attaches the bearer token, parses the standard response envelope, parses standard errors, redirects on \texttt{UNAUTHORIZED}, renders permission state on \texttt{FORBIDDEN}, and displays request IDs for support debugging.

\section*{Acceptance Criteria}
The admin dashboard is done only when protected routes exist, API status panel exists, KYC queue and user list exist, audit log viewer exists, role permission states exist, loading/empty/error states exist, and tests cover core routes and permissions.
